### Open coding (all 48 transcripts read; per-run summaries are regenerated from the JSON with `scripts/eval-traces.sh` and are not committed)

With the plugin, every doctor run fired `/superskills-doctor`, located the script through the
plugin root, ran it with `--root/--home`, reproduced the table and verdict, and named the
next action without running it. Tool calls per run: 3–5.

Without the plugin, Claude hand-rolled the investigation (5–11 Bash calls: `find`, `cat`,
`diff -r`, `shasum`, `od`). It reliably found the two discoverable facts (the unlinked
`clean-code`, the stale `.codex-plugin` manifest). It then went wrong in the same way in most
runs: it explained the tool's own machinery incorrectly and recommended harmful fixes —
"`gstack` is an orphaned, dead directory, delete it", "copy `clean-code` into the home
directory by hand", "the vendor markers are inverted, add them to `tdd` and `debug`",
"`setup` is a no-op, that's the root cause, rewrite it", "`marketplace.json` is malformed",
"`1.80.0.0` doesn't parse as semver". Only the release-check prompt, which *told* it what
a vendor copy was, produced a domain-correct baseline.

Marketing runs fired the skill in 6/6 with-runs, but under the directory basename
(`superskills-marketing:description`, `:pricing`) rather than the frontmatter name the
graders expected — the loader ignores `name:` (confirmed in the main plugin too:
`superskills:composition-patterns`, not `vercel-composition-patterns`). The skill's
contribution was visible in the text (150–160 character window, mobile-truncation rule,
value-metric and decoy-effect guidance on the pricing page) but the outcome graders were
too coarse or too strict to register it.

## What the evidence supports

- **Item 1 (doctor) improves effectiveness on every doctor case** once the rubric measures what the baseline actually gets wrong: Δ +0.20 to +0.30 with all with-arm runs at 1.00, 20/20 skill selections on direct, symptom and ambiguous phrasing, 0 mutating commands in 40 runs, 0 false "ready" verdicts, and 3–5 tool calls instead of 5–11. The contribution is not *finding* facts (the baseline finds them) but *interpreting* them correctly and naming the canonical fix. The baseline recommended deleting a dependency or hand-copying skills in 9/12 (run 1) and 7/8 (run 2) runs.
- **Item 2 (marketing plugin) works end to end** only after the shim-tree fix; run 1 proved the naive manifest exposed the wrong names. Skill selection 6/6 under the intended names; outcome Δ is 0 on both marketing cases after human labelling, because a plugin-less Claude already writes acceptable marketing copy — the skills add specific rules (150–160 character window, mobile truncation, decoy-tier and value-metric guidance) that the rubric only partly captures. The marketing plugin was loaded by path in the eval, not through the marketplace `source` entry; that install path is schema-validated only.
- **Item 7 (conventions)** is measured indirectly through the doctor skill's read-only and honest-verdict rows, both perfect; there is no separate ablation of the conventions themselves.
- **Items 3, 4, 5 and 6** are verified by validators and bats, not by agent runs (matrix above). Item 4's Codex `interface` block turned a hard validator failure into a pass; item 5 caught a real defect (mirrored skills without frontmatter).
- **Negative controls** held in both runs: "update superskills" fired only `/superskills-upgrade`; an off-topic question fired nothing.

### Limits, stated plainly

- Counts are small (2–3 runs per arm per case); treat the Δs as direction, not precision. The KB's ~100 examples per failure type was not reached.
- The human labels are mine (Claude, reading the archived transcripts), not the repo owner's.
- `no-false-ready` never met a dishonest reply, so its true-positive rate is unmeasured.
- The eval sandbox cannot read `$HOME`; doctor cases run against a scaffolded fixture. In runs 1 and 2 its `setup` was a 10-byte stub, which the baseline sometimes diagnosed as the root cause; the fixture now carries a realistic abridged installer (not yet re-run at full scale).
- Cursor manifests are validated only against the documented "name is the only required field"; no Cursor tool was available to load them.
- `marketing-skills/plugin-skills/` introduces committed symlinks. A Windows checkout without `core.symlinks` gets plain text files and the marketing plugin will not load there; `./setup` installs are unaffected.
- The marketplace install path was exercised afterwards in an isolated config (`CLAUDE_CONFIG_DIR=<scratch>`): `claude plugin marketplace add <repo>` then `install superskills-marketing@superskills` and `install superskills@superskills` both succeed at 2.24.0, and all 174 shim links resolve inside the plugin cache copy. Note the root plugin's `source: "./"` copies the whole repo (vendor, evals, marketing-skills) into the cache.

### Changes from the `/qa-full` pass (2026-09-16, after this report's runs)

`/qa-full` on this branch (`qa-full-reports/qa-full-main-2026-09-16.md`, local) ran `/review`
