# Design variations

1. **Pick axes** that change the design, not the paint: layout, information hierarchy, density, interaction model, visual tone. Name them.
2. **Specify each variant up front** (one line per axis) before building. Variants must differ on at least two axes; three takes on the same layout is one option.
3. **Fidelity:** wireframe = grayscale, system font, boxes and labels, real content structure, no styling polish. Hi-fi = full tokens from /design-direction or the existing system.
4. **Build all in one file or one comparison page** with labelled sections, so the user can scan them side by side. Include at least one bold, off-pattern option.
5. **Stay honest:** same real content in every variant. Note the trade-off of each in one line. Recommend one, and let the user choose.
